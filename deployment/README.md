# One-command local installation

Install and start Docker Desktop (or Docker Engine with Compose), then run this
from the repository folder:

```sh
bash scripts/start.sh
```

Open [the app](http://localhost:3000). First follow its link to create your local
n8n owner account, then return and enter your OpenAI API key to complete setup. Setup checks that the key can read the OpenAI model list. It then imports
all eight workflows, connects their OpenAI credentials and publishes the three core sub-workflows and three
analysis webhooks. Use **Örnek soruyu kullan**, then **Uzmanları çalıştır** to
run a real question. Actual model calls incur OpenAI usage charges and require
available API credit and model access. Model-list verification alone cannot
confirm those permissions or available credit.

On Windows, double-click `scripts/start.cmd` instead of running the Bash command.
Windows Docker Desktop must use Linux containers. The Windows launcher has been
reviewed but has not been executed on a Windows machine.

No host Node.js or manual workflow imports are required. The first build downloads
the images and dependencies and can take several minutes. Existing root and UI
`.env` files are excluded from the images, and the startup script ignores root
`.env` settings. Runtime settings can be supplied as shell environment variables.

```sh
APP_PORT=3001 N8N_EDITOR_PORT=5681 bash scripts/start.sh
```

The packaged instance uses its own Compose project and named volume. Ports bind
to localhost. This package is intended for one trusted local operator. Public
hosting requires authentication, HTTPS and per-user access controls before
exposing the app or its setup endpoint.

## Persistence and maintenance

The `n8n_data` volume contains the database and the encryption key generated by
n8n. The `internal_access` volume contains the service authentication token. The `evaluation_history` volume holds the local SQLite evaluation history shared by browsers on the same installation. Back up all three volumes together. OpenAI credentials are encrypted by n8n. During
import, the credential JSON exists only in a private temporary directory on the
container's memory-backed `/tmp` and is removed after import.

Encryption protects the stored credential, but the encryption key is in the same
volume. A person or agent with sufficient browser, terminal, Docker or n8n access
can retrieve or use the credential. A password field only masks its on-screen
display. The setup form clears the field when submitted. The setup code does not
include the key in logs or API responses. Browser-to-local-service traffic uses
local HTTP; requests from the setup service and n8n to OpenAI use HTTPS. This
package has not received an independent security audit.

The completion marker is written after imports and publication succeed. Restarting
preserves credentials and workflows and skips reimport, preserving editor changes.
If setup is interrupted before completion, rerun setup to retry the same workflow
and credential IDs. This package uses a dedicated fresh instance. Do not attach
an existing n8n volume to it.

Stop and resume without deleting data:

```sh
docker compose --env-file deployment/compose.env stop
bash scripts/start.sh
```

View service logs:

```sh
docker compose --env-file deployment/compose.env logs --tail=100
```

After setup, manage or replace the OpenAI credential in the
[n8n editor](http://localhost:5680). The owner account must be created before saving the first OpenAI key. The setup screen accepts a key only until installation completes.
Rebuilding the package does not automatically replace previously installed
workflows. Future workflow upgrades must be imported deliberately after backup.

## Optional Google Docs export

Analysis works before Google is configured. All eight workflows are imported,
but the Google Docs webhook and the chat-trigger workflow remain unpublished
until their Google dependencies are configured.

1. Open the n8n editor and create your owner account if prompted.
2. Set up Google Cloud OAuth access for the Google Drive and Google Docs APIs.
   Use the redirect URL shown in each n8n credential.
3. Create Google Drive OAuth2 and Google Docs OAuth2 credentials in n8n.
4. In **Multi-Agent UI - Google Docs API**, select those credentials in the Drive
   and Docs nodes. Replace `REPLACE_WITH_GOOGLE_DRIVE_FOLDER_ID` with your target
   folder ID and check all remaining resource selections.
5. Publish that workflow, then enable the export button:

```sh
GOOGLE_DOCS_ENABLED=true bash scripts/start.sh
```

Supply the same environment setting on later startup commands to keep the button
enabled. The standalone chat-trigger workflow can be configured and published
separately if needed.

## Implementation and checks

- n8n is pinned to `2.46.6`.
- `setup-server.mjs` supervises n8n and runs its CLI while n8n is stopped during
  installation. Stable workflow IDs preserve sub-workflow references.
- `workflows.mjs` prepares copies of repository exports, removes source-instance
  ownership and Google credential references, and assigns the local OpenAI ID.
- Header credentials protect every imported UI webhook. The UI reads its token
  from a read-only shared volume. Setup service requests require the same token.
- Existing packaged installations receive a one-time webhook authentication
  migration that preserves stored workflow edits and Google credential selections.
- The UI proxies setup requests internally. The setup service port is not
  published to the host, and browser writes require the UI's origin. Explicit localhost origins reject
  DNS-rebinding Host values. Server-side limits cap request bytes, active requests
  and request rate. These limits are per-process and are not a spending budget.

```sh
node --test deployment/workflows.test.mjs
npm run validate
npm --prefix ui test
npm --prefix ui run lint
```

The setup automation uses the documented n8n
[credential and workflow import and publication commands](https://docs.n8n.io/hosting/cli-commands/).

## Download and daily use

On the GitHub repository page, choose **Code → Download ZIP**, or clone the
repository. If you downloaded the ZIP, extract it first. Run the launcher from
the project folder so Docker Compose can find its configuration. Docker installs
the UI dependencies inside the image. You do not need Node.js, npm, or a local
`node_modules` folder for this installation.

After installation, open the app, enter a question, optionally attach a CSV,
review its preview and column notes, then run the experts. Use the default model
or enter a model ID available to your API account. Save to Google Docs only after
its optional setup is complete. For sensitive data, review the outbound data flow
in `SECURITY.md` first.

To stop, run the `docker compose ... stop` command above. Running the startup
launcher again preserves credentials and workflows. Do not use `down --volumes`
for a normal shutdown, because that removes stored credentials and configuration.
Before an update, stop the services and make a backup of the named volumes.
Database upgrades can prevent downgrading without restoring the backup.

Build a clean distribution ZIP locally:

```sh
python3 scripts/package-release.py
```

This excludes `.git`, local environment files, dependencies, generated reports,
Docker volumes and temporary files. `.gitignore` does not remove files already
tracked in Git or erase their history. Review the Git repository separately
before publishing it. The project owner still needs to choose the project's
redistribution license; the archive does not assign one automatically.

Verify a downloaded release before extraction by keeping the ZIP and its checksum
file together. On macOS/Linux:

```sh
shasum -a 256 -c ortak-akil-source.zip.sha256
```

On Windows PowerShell, compare the following output with the checksum file:

```powershell
Get-FileHash .\ortak-akil-source.zip -Algorithm SHA256
```

A checksum detects file changes. Obtain it from a trusted release source as well.
Read the outstanding container findings before deciding where to run the preview.
